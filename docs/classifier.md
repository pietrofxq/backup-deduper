# Classifier reference

The classifier turns a list of `file` rows + a preset into a list of
`PlannedAction`s, `ReviewPair`s, and `EmptyDir`s. Top-level entrypoint:
[src/classifier/rules.ts `classifyAll`](../src/classifier/rules.ts).

## Precedence

```
1. CRUFT — STOP on match per file
   1a. preset whitelist  (always wins)
   1b. always-on basenames: Thumbs.db, desktop.ini, .DS_Store, ehthumbs.db
   1c. preset cruft rules (in declared order)

2. DUPLICATE — STOP for the entire group
   2a. group by sha256_hex (only files that have a hash)
   2b. within each collection: pick canonical via path priority,
       non-keepers → reason = 'duplicate_within_collection'
   2c. across collections: primary's representative wins,
       others → reason = 'duplicate_cross_collection',
       lex-smallest collection wins if no primary participates

3. NAME COLLISION (REVIEW only — never auto-acts)
   - cross-collection only
   - same basename, different sha256
   - exclude any file already targeted by passes 1 or 2
   - emit (a, b) pairs into review_item

4. KEEP — default
```

Cruft beats duplicate so the audit log records the most informative reason
(a `.exo` file that's also a duplicate is logged as `cruft_preset_exo`,
not `duplicate_cross_collection`).

## Whitelist semantics — non-negotiable

Whitelist runs **before** the always-on basename list and **before** preset
cruft rules. The Samsung preset whitelists `Android/media/` because that's
where WhatsApp stores user media; without the whitelist a `Thumbs.db` or
`*.exo` rule could sweep real photos.

When you add a new preset, ask: "Is there any folder under this preset's
domain where the cruft rules would harm user content?" If yes, add it to
`whitelist`.

Source: [src/classifier/cruft.ts:30–43](../src/classifier/cruft.ts).

## Match kinds

Both `CruftRule` and `WhitelistRule` support four kinds. Same matching
logic, applied to forward-slash DB rel-paths:

| kind | semantics | example |
|------|-----------|---------|
| `basename` | `relPath`'s last `/`-separated segment equals `pattern` | `{kind:'basename', pattern:'Thumbs.db'}` |
| `extension` | `path.posix.extname(relPath).toLowerCase() === pattern.toLowerCase()` | `{kind:'extension', pattern:'.exo'}` |
| `path_prefix` | `relPath.startsWith(pattern)` (raw `startsWith`, **unanchored** — known limitation, ROADMAP backlog #11) | `{kind:'path_prefix', pattern:'Android/data/'}` |
| `glob` | single-segment glob: `*` → `[^/]*`, `?` → `[^/]`. **No `**`.** Anchored both ends. | `{kind:'glob', pattern:'IMG_*.jpg'}` |

> **Watch out:** `path_prefix` is unanchored. `Android/data` would also
> match `Android/database/foo`. Always include the trailing `/` in
> `path_prefix` patterns. ROADMAP backlog #11 is to enforce this in the
> schema.

## Preset shape

```ts
// src/presets/types.ts
{
  name: string,                            // unique
  description?: string,
  cruft_rules: Array<{                     // applied in order
    id: string,                            // shows up in reason: cruft_preset_<id>
    kind: 'basename'|'extension'|'path_prefix'|'glob',
    pattern: string,
    description?: string
  }>,
  whitelist: Array<{
    kind: 'basename'|'extension'|'path_prefix'|'glob',
    pattern: string
  }>,
  path_priority: string[]                  // path_prefix patterns; index 0 = highest priority
}
```

Validated by zod when loaded from the `preset` table
([src/presets/registry.ts](../src/presets/registry.ts)). A row that fails
validation throws on load, **not** silently ignored.

## Built-in presets

### `Samsung Android phone backup`

[src/presets/samsung-android.ts](../src/presets/samsung-android.ts).

- Cruft: `*.exo`, `Android/data/`, `Android/obb/`.
- Whitelist: `Android/media/` (WhatsApp + co.).
- Path priority (canonical-keeper): `DCIM/Camera/`, `DCIM/Screenshots/`,
  `DCIM/Restored/`, `DCIM/Shared/`, `DCIM/Snapchat/`, then everything else.

### `Minimal`

[src/presets/minimal.ts](../src/presets/minimal.ts). No preset cruft rules,
no whitelist, no path priority. Always-on rules still apply (empty folders,
OS metadata).

Use this when none of the canned presets fit and you want maximum
conservatism.

## Path priority and canonical keeper

Within a (collection, sha256) group, the keeper is the file whose
`rel_path` matches the **earliest** prefix in `path_priority`. Paths that
match no prefix are tied; among ties, lex-smallest `rel_path` wins (stable,
deterministic).

Across collections, the primary collection's representative wins. If the
primary has no member of the hash group, the lex-smallest collection's
representative wins.

Source: [src/classifier/dedup.ts](../src/classifier/dedup.ts).

## Reasons (the `reason` column)

Generated by [classifier/cruft.ts `reasonStringFor`](../src/classifier/cruft.ts)
and [classifier/dedup.ts](../src/classifier/dedup.ts):

| reason | source |
|--------|--------|
| `cruft_os_metadata` | always-on basename match |
| `cruft_preset_<rule.id>` | preset cruft rule match |
| `cruft_empty_folder` | empty-dir sweep at end of `executeQuarantine` |
| `duplicate_within_collection` | dedup pass, within-collection loser |
| `duplicate_cross_collection` | dedup pass, cross-collection loser |

If you add a new reason, **also**:

1. Update the audit-page filter dropdown source (`listAuditReasons` in
   [src/db/queries.ts](../src/db/queries.ts)) — already returns all
   distinct values, but make sure your new value lands in real DB rows.
2. Add a row in the table-driven classifier test
   ([tests/unit/classifier.test.ts](../tests/unit/classifier.test.ts)).

## Known limitations

- **`path_prefix` unanchored** — see above. ROADMAP backlog #11.
- **No `**` in glob** — single-segment only by design (keeps the matcher
  small and correct). Use `path_prefix` for tree-wide matches.
- **Empty-dir cruft sweep ignores preset whitelist.** A whitelisted
  `Android/media/` directory that ends up empty after a quarantine pass
  will still be removed. ROADMAP backlog #9.
- **Cruft files with NULL hash skip the re-verify-before-rename gate.**
  Documented limitation. ROADMAP backlog #25.
- **Name-collision pairs are O(n²) per basename group** — pathologically
  large groups (10k+ files with the same basename across collections) will
  hurt. ROADMAP backlog #27.
